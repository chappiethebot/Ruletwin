# RuleTwin — method note

**Rental Housing Law Navigator · v5 participant release · snapshot `snap-96c4ceacda7b` · as of 2026-10-01. Legal information, not legal advice; not reviewed by counsel.**

**What it does.** For each of the 500 sample addresses, RuleTwin reports which rental-housing rules apply on a chosen date: in force, superseded by a local rule, not yet effective, pending or unknown. Every answer carries its citation, source document, retrieval date and as-of date. It also reports the addresses affected by the five supplied change tests (T1–T5).

**Module A — automated extraction.** Each corpus document with supplied text goes to an LLM (Claude Sonnet via structured output, one call per document chunk, cached). The model returns category, jurisdiction, status, effective date, requirement (English and Spanish), key value, penalty, citation, a quoted span, and the coverage conditions as an allowlisted condition tree. Every quoted span must match the source text character-for-character, or the record is rejected. Records for the same law across documents are merged automatically; nothing is hand-written. All 89 manifest entries have a recorded disposition (47 with rules, 9 with no in-scope rule, 33 link-only), with 0 extraction errors. Result: 48 rules; key values on 45, source-stated penalties on 17.

**Module B — address lookup.** The legal city comes from the US Census Geocoder (incorporated place, county). A match is accepted only if it carries the input's house number. Postal city is never trusted. Remaining identity gaps use official public evidence: municipal assessor rolls, the Census ZIP–place relationship file with MassGIS street corroboration, and the NJ geocoder plus municipal boundaries. One address (A0346) stays ambiguous and reports only conclusions shared by both candidate cities. A single deterministic TypeScript engine, shared by the website and the exports, evaluates each rule with true/false/unknown logic over building facts, dates and local-versus-state precedence. Where facts are missing, constraint reasoning checks every admissible value. It proves answers that cannot change, and otherwise returns the outcome for each value and the one decisive question. Year built is not a certificate-of-occupancy date: a cutoff inside the build year stays unknown. Owner facts are never inferred.

**Module C — change tracking.** Every case is evaluated through the same dated path as address reports. T1: 250 California addresses go from not yet effective to applies. T2: 90 addresses, Hoboken and Jersey City only, none in Newark. T3: 140 NJ addresses, with 90 flagged for a possible conflict with the local bans. T4: both MA bills stay pending; 110 addresses would be affected if enacted, evaluated as a labelled hypothetical. T5: empty set, since a struck ballot question never becomes law.

**Results.** Lookups: 3,373 applies, 289 superseded, 140 not yet effective, 440 pending, 511 unknown. The unknowns fall on 207 properties, averaging 1.8 decisive questions each.

**Honest limits.** Three rules quote team-captured copies of link-only pages: the Hoboken and Jersey City algorithmic bans (D037) and the MA ballot question (D059). They are marked `source_in_supplied_corpus: false` and earn no citation credit. Santa Ana NS-3090, Hoboken rent control and Newark rent control have no corpus text, so no rule is reported for them. Exemptions that no data can test are treated as disclosed presumptions; `STRICT_EXEMPTIONS=1` keeps them unknown instead. Historical versions before current text are not modelled.

**Validation and reproducibility.** 50 unit tests and 16 browser journeys pass. Publication fails closed on schema, exact-quote, ID or evidence errors. Snapshots are content-addressed. `submission/audit_log.json` records input and output hashes and the rerun commands. Our 37-case AI-reviewed reference set (31 of 33 definite answers correct) is an internal check, not an official score.
