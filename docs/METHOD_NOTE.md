# RuleTwin — method note

Draft for the participant pack's live demo and one-page method note. Describes the current prototype, reviewed 2026-10-04; refresh after repairs and the final release. **Legal information, not legal advice. Not reviewed by counsel.**

**Problem and scope.** RuleTwin answers which rental-housing rules apply at a sample address on a chosen date and which addresses a supplied law change affects. It uses the provided CA/NJ/MA corpus: six categories, ten cities represented in law and 500 properties in nine cities. Santa Ana is extraction-only. It is a bounded prototype, not nationwide coverage or a compliance certification.

**Method.** An automated LLM extractor produces structured candidates from supplied public text and labeled supplementary pages. Candidate quotes are matched against source text; consolidation produces official rule records plus allowlisted predicate expressions. Cached responses and a document ledger record extraction provenance. Link-only disposition does not establish that an unavailable source's provisions were extracted.

Census incorporated-place results resolve legal city; postal city is insufficient. Supplied building facts and evidence records feed one deterministic TypeScript engine shared by the CLI and website. It evaluates dates, conditions, exemptions and local/state interactions using true/false/unknown logic. The UI shows source text, query date, status, reasoning and conditional questions. Questions are hypothetical inputs rather than verified property evidence.

Change tracking evaluates the supplied T1–T5 cases and supports dated comparisons. Pending-bill scenarios remain distinct from actual law; a failed measure must not create protection. Sources, evidence and outputs are stored in snapshots for local reporting. The application serves frozen sample data without requiring an LLM request for each lookup.

**Evidence.** Active export `snap-412366cbb46f` has 53 unique rules, exact headline quotes/offsets in pinned sources, independent schema validation and all 500 sample IDs. T1–T5 totals are 250, 90, 140, 110 and 0; T3 has 90 conflict flags. Current code passes 50 tests and 16 browser journeys. Working and published default-date results agree: 691 unknown pairs across 339 properties, with zero lookup mismatches. These are structural/execution checks, not organizer scores. The latest validator changes remain unpublished, so the active engine identity differs from current local code.

**Limits and repairs.** Focused regressions cover joint branches, contradictions, conflicting facts/dates, change losses, proposal matching, input contracts and publication validation. Snapshot identity and overwrite protection have repairs. Unverified CO/affordability/exemption assumptions, incomplete source/effect coverage, historical versions and complete offline replay remain gaps. The 37-case AI-authored reference replay has 32 correct definite answers, 4 correctly indeterminate answers and one overclaim (C35); it is not an independent accuracy benchmark. Missing owner facts and A0346's legal city remain unresolved.

**Reproduce.** Follow the repository README, build and start locally, then run `npm test` and inspect the three files under `submission/`. The supplied pack lacks an official scorer/key.
